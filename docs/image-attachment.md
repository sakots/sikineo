# Siki投稿欄への画像引き渡し

## 対象

neoで描いた画像を、描画開始時のSikiの5chスレッドの投稿欄へ渡す。本文・名前・メール欄を置き換えず、レスは自動送信しない。送信は利用者がSikiで行う。PNGファイルのダウンロード機能は追加しない。他サイトや500×250px以外の描画サイズへの汎用対応は行わず、未対応の対象は明示的に拒否する。

## Sikiとの契約

参照基準は公式Linux版Siki 0.43.12。汎用プラグインには安定した画像添付APIが公開されていないため、同版の既存描画処理を利用する。

- `assets/main.js`の`saveDrawing(location, dataUrl, 'png')`は、スレッドURLをルーティングし、Sikiのお絵かき画像領域へPNGを書き込む。その後`drawingUpdated_<location>`で投稿欄へ通知する。
- `assets/render.js`の投稿欄は`drawing`状態が有効なときにこの画像を表示・利用する。投稿時の既存処理が`oekaki`として扱う。
- Siki所有のレンダラーから`rendererApi.invoke('invokeNNC', 'saveDrawing', null, location, dataUrl, 'png')`を呼び、既存の保存・通知を再利用する。プラグイン独自のファイル名規則でSikiの画像領域へ直接書き込まない。
- `core:dispatch.action`の`TAB_SET_VALUES`で指定タブの`drawing`だけを有効にし、`TAB_POSTAREA_SET`で指定投稿欄を開く。現在のタブへフォールバックする`THREAD_SWITCH_VALUE`や`tab:post.open`は使わない。
- 対象タブ・URL・レンダラーを確認してから操作する。別タブへの切り替えで添付先を変更しない。対象を閉じた場合はエラーとし、現在の別タブへ添付しない。
- 既存のお絵かき画像は、利用者が画像引き渡しボタンを押した時点で新しい画像に置き換わる。レスの送信、本文変更、画像の自動投稿は行わない。

参照: [公式汎用プラグイン資料](https://sikiapp.net/plugin-development/)、[公式配布物](https://github.com/romtenma/siki-asar-releases/releases/tag/v0.43.12)。内部APIなので、別のSikiバージョンに同じ互換性があるとは保証しない。

## 起動とサイズ

Sikiのユーザーコマンド`neoで描く`の第1パラメータを次に変更する:

```text
http://127.0.0.1:57831/
```

コマンドパレット経由では`O.tabid`などのテンプレート値が空になることを実Sikiで確認したため、対象情報をURLへ埋め込まない。描画ページを開く際にSiki所有のレンダラー内の表示中スレッドを確認し、タブIDと正規化URLを取得する。対象がない場合や複数ウィンドウで曖昧な場合は開始を拒否する。その後の添付では、この取得済み対象だけを使用する。

サーバーは対象をSikiで確認し、ページごとのランダムなセッショントークンに固定する。描画ページには添付先のタイトルとサイズを表示する。サイズはSikiの`site_option.drawing_size`を使う。5chでは500×250pxである。既存300×300の画像を自動で引き伸ばさない。

旧v0.2の`127.0.0.1:57830`とはオリジンを分離する。neoは異なるサイズの一時保存画像を新しいキャンバスへ復元すると画像を切り取るため、旧300×300の保存データを誤って読み込まないようにする。旧オリジンの保存領域は削除・移行しない。新画面の一時保存は同一オリジンで共有されるため、複数の描画画面は同時に使わない。

## neo本体

利用者指定の[neo.js](https://oekakibbs.moe/apps/neo/neo.js)と同配布元の[neo.css](https://oekakibbs.moe/apps/neo/neo.css)を描画ページから直接読み込む。本体の手動配置・同梱・プラグインサーバーによる代理取得は行わない。画面を開く際に外部接続が必要で、配布元の更新が実行されるコードに反映される。リソースの取得に失敗した場合はエラーを表示して引き渡しを無効にする。

neoの`getImage()`で表示中の描画レイヤーを白背景へ合成し、元の描画サイズのPNGデータURLを取得する。UIやズーム倍率は含めない。自動リサイズ・非可逆変換・投稿先への通信は行わない。

## HTTPとUIの境界

- ローカル待受と静的ファイルの許可リストを維持する。
- 描画ページへの応答時に、サーバーで対象を確認してからセッション情報をHTML属性用にエスケープして埋め込む。
- `POST /attachment`はJSONの`token`と`dataUrl`を受け付ける。対象スレッド情報そのものはクライアントから受け取らず、保存したセッションから取得する。
- POSTは待受URLと完全一致する`Origin`、JSON Content-Type、有効なセッショントークンを必須とする。受信上限は2MiB。これはローカル受信の保護であり、5chの投稿上限を保証する値ではない。
- 実PNGとしてデコードでき、対象サイズに一致する画像だけを渡す。送信先に合わせた再圧縮や上限回避はしない。投稿時のサーバー側制限はSikiの既存処理で扱う。
- 引き渡し中はボタンを無効化する。成功と「未送信」を明示し、エラー時もキャンバスを保持する。失敗を成功として表示しない。
- CSPではneoのJavaScript・CSSの指定URLだけを外部リソースとして許可する。画像引き渡しの通信は同一オリジンに限定し、CORS許可は追加しない。指定配布元の実行コードを信頼する前提で、トークン・画像・本文はログへ記録しない。

## 検証

実装前にHTTP経由の拒否境界とセッション状態の回帰テストを書く。実Sikiの隔離プロファイルで、画像プレビュー、本文保持、開始後の別タブへの切り替え、対象タブを閉じた場合の失敗を確認する。試験中もレスの送信操作は行わない。外部の掲示板へ投稿して検証する必要はない。

## v0.3.0での検証結果

2026/11/05、Node.js 26.12.1、pnpm 12.15.0、公式Linux版Siki 0.43.12、配置済みのneo 1.8.12で確認。

- `pnpm test`: 3件成功。実装前には対象付き描画ページとPOSTの拒否境界のテストが失敗することを確認。
- `pnpm pack`の成果物を隔離プロファイルへ展開し、開発依存なしで起動。neo本体は別途配置し、配布アーカイブには含めないことを確認。
- Sikiを`--ozone-platform=headless --disable-gpu --no-sandbox`で起動して検証。これらは隔離試験用のオプションであり、通常利用の推奨設定ではない。
- コマンドパレットから起動し、実マウス操作で500×250pxの描画画像の白以外の画素が0から201へ変化することを確認。引き渡し後のネイティブ保存PNGが、neoの合成PNGと一致した。
- Sikiの通常投稿欄に500×250pxのプレビューが表示され、本文・名前・メール欄が変更されないことを確認。
- 描画開始後に別の5ch形式タブへ移動しても、元の対象だけに新しいPNGが保存され、移動先の画像・本文・選択状態を変更しないことを確認。
- 元の対象タブを閉じると引き渡しが失敗し、描画が残り、別タブへ画像を添付しないことを確認。
- ウィンドウ型投稿欄でも、対象の描画状態が`true`となり、保存PNGが一致し、別ウィンドウの本文が保持されることを確認。Sikiの当該ウィンドウには画像サムネイルの表示はなかった。
- 特殊文字・置換記号・scriptタグを含むタイトルを表示しても文字列が保持され、スクリプトが実行されないことを確認。
- 描画ページでは外部接続を許可せず、ブラウザのコンソールエラー0件を確認。

掲示板へ投稿せずに検証するため、5chのURL形式に沿う検証用スレッドURLでSikiのネイティブ投稿欄を使用した。実スレッドへのレスの送信や投稿先のサイズ制限通過は検証していない。通常のデスクトップ合成表示、Windows・macOS、切り離したスレッドウィンドウからの起動も未検証。複数の対象ウィンドウがあり開始先を一意に決められない場合はエラーにする。
