# neo描画画面の手動起動

## 対象と選択

- Sikiのユーザーコマンドを操作したときだけ、ブラウザビュー内でneo描画画面を開く。Siki起動時には開かない。
- neo本体は利用者が別途取得・配置する。このリポジトリと配布アーカイブには同梱しない。
- 対象は描画まで。5chへの投稿、画像の書き出し、キャンバスサイズ変更は含めない。

## 連携方式

Sikiの`startup`処理からNode.js標準のHTTPサーバーを`127.0.0.1:57830`で起動する。Sikiのユーザーコマンド`uri:open-browserview`に`http://127.0.0.1:57830/`を渡して描画画面を開く。

この方式を選ぶ根拠:

- [公式プラグイン仕様](https://sikiapp.net/plugin-development/)は、起動時のNode.js処理を提供するが、独自コマンド登録APIは定義していない。
- [公式コマンド一覧](https://sikiapp.net/command/)は`uri:open-browserview`を公開している。
- Siki 0.43.12の[公式配布ASAR](https://github.com/romtenma/siki-asar-releases/releases/tag/v0.43.12)内の`assets/render.js`では、`BROWSERVIEW_OPEN`処理が`http(s):`または`siki:`以外のURLに`https://`を補う。この経路ではローカルの`file:` URLは利用できない。
- 同ASARの`assets/main.js`では、`reload_plugins()`が`mainScript(settings, tools)`を呼ぶ。非公開のイベント名やElectronメニューへの差し込みは使わない。

参照基準はSiki 0.43.12とする。確認範囲は末尾の検証結果を参照。ASARのSHA-256は`128635110097e08eb2440229cace587b33c78da75efc4dd1ff6194b3abec9453`。

## neo本体の取得

取得元は利用者指定の`https://oekakibbs.moe/apps/neo/neo.js`とする。確認時のファイル先頭表記はPaintBBS NEO **1.8.12**。配布URLは固定バージョンURLではないため、取得したファイルをローカルに保持し、起動時の自動更新は行わない。

次の2ファイルを取得し、プラグインフォルダ内の`neo/`へ配置する:

- [neo.js](https://oekakibbs.moe/apps/neo/neo.js)
- [neo.css](https://oekakibbs.moe/apps/neo/neo.css)

```text
sikineo/
├─ package.json
├─ dist/
├─ public/
└─ neo/
   ├─ neo.js
   └─ neo.css
```

取得・配置後は外部ネットワークへの接続なしで描画できる。本体が未配置の場合はHTTP 503で配置案内を表示する。配置後はページを再読み込みすればよく、Sikiの再起動は不要。

上流の`package.json`にはneo本体のライセンス指定がなく、JavaScript先頭のMIT表記は同梱のlz-stringだけを対象とする。neo本体をMITライセンスと表記せず、上流の著作権表示も削除しない。配布条件の確認は未解決のため、取得済みの`neo/`もGitと配布対象から除外する。

## Sikiでの設定

1. プラグインを配置・有効化し、Sikiを再起動する。
2. Sikiの設定の「ユーザーコマンド」で次のコマンドを追加する。
   - 名前: `sikineo.open`
   - 表示名: `neoで描く`
   - 実行コマンド: `uri:open-browserview`
   - 第1パラメータ: `http://127.0.0.1:57830/`
3. コマンドパレット等から`neoで描く`（`user:sikineo.open`）を実行する。必要ならSiki側でショートカットへ割り当てる。

既存の`components/usercommand.js`やキーマップをプラグインから上書きしない。[旧形式の公式ユーザーコマンド資料](https://sikiapp.net/usercommand/)の`type: 'emit'`には依存しない。

## 描画とデータ

- 上流の現行設定形式である`.neo-applet-paintbbs`と`Neo.params.paintbbs`を使用する。キャンバスは300×300ピクセル。
- Electronでは上流が自動開始を行わないため、上流の初期化後に`Neo.start(false)`を呼ぶ。旧Electronアプリ用の`Neo.start(true)`は使わない。
- 「投稿」は非表示にし、上流の`paintBBSCallback('check')`でも送信を中止する。投稿先や認証情報を設定しない。
- neoのローカルストレージによる一時保存・復元は上流の挙動を維持する。確実な保存を保証するものではない。ストレージ削除やSikiのプロファイル変更で失われることがある。同じURLを複数タブで開くと一時保存を共有するため、描画は1タブで行う。
- 起動通知`plugin:sikineo:ready`はHTTPサーバーの待受完了後に発火する。描画ページが開いたことやneo本体が配置済みであることの通知ではない。

## HTTPの境界

- 待受先はIPv4ループバックだけ。ポート57830が使用中なら起動を失敗させ、Siki側のプラグインエラーログへ伝える。別ポートへの自動切り替えは行わない。
- 公開するURLは描画ページ・配置案内用のCSS・描画用JavaScript・利用者が配置したneo本体だけ。任意のパスやプロファイルファイルは配信しない。
- `Host`は実際の待受アドレスと一致するものだけを許可し、DNSリバインディングによる別ホスト名からのアクセスを拒否する。
- GETとHEADだけを受け付け、CORS許可は付けない。投稿用APIは作らない。
- CSPで外部スクリプト・通信・フォーム送信を許可しない。neoの生成スタイルとデータURL画像に必要な範囲だけ許可する。
- 同じPCの別プロセスによるアクセスは認証しない。プラグインの実行コードと利用者が配置するneo本体は信頼済みのものだけを使用する。

## 検証方針

- 実装前に、実HTTP経由で未配置時の案内と任意ファイル配信の拒否を確認するテストを書く。
- 実ブラウザで配置案内を確認後、上流の実ファイルを配置してオフラインで起動する。
- 実マウス操作によるストローク後に合成画像の画素が変化し、Undo/Redoで戻ることを確認する。Canvasへの直接描き込みを動作確認の代用にしない。
- Sikiの実行環境を用意できる場合は、隔離プロファイルでユーザーコマンドからの起動まで確認する。ブラウザ単体の成功をSiki実機確認済みとは扱わない。

## 検証結果

2026/11/05、Node.js 26.12.1・pnpm 12.15.0・Linuxで確認。

- `pnpm test`: HTTPの配置状態遷移と配信境界の2テストが成功。実装前には配信モジュール不在で失敗することを確認。
- `pnpm pack`の成果物を隔離したSikiプロファイルへ展開し、利用者指定URLの実ファイルを別途配置。開発用`node_modules/`なしでSikiが読み込み・待受に成功。
- 公式Linux版Siki 0.43.12を`--ozone-platform=headless --disable-gpu --no-sandbox`で起動し、コマンドパレットの`neoで描く`からブラウザビューを開くことを確認。これらの起動オプションは隔離検証用であり、通常利用の推奨設定ではない。
- 同ブラウザビューでneo 1.8.12と300×300の合成画像を確認。実マウス操作で白以外の画素が0から142へ変化し、UIのUndoで0、Redoで142へ戻ることを確認。ゲスト描画ページのスクリーンショットでストローク・操作ボタン・著作権表示を確認。
- ローカルホスト以外への接続を禁止したChromiumでも起動。Electronを含むUser-Agentで上流の自動開始が抑止される場合も、明示的な`Neo.start(false)`によって初期化できることを確認。
- 投稿ボタンが非表示、投稿前コールバックが`false`、描画ページのコンソールエラーが0件であることを確認。
- ポート使用中は`EADDRINUSE`で失敗し、`ready`を誤通知しないことを確認。
- 本体未配置時の案内も実ブラウザで確認。

未確認: 通常のデスクトップ環境でのウィンドウ合成・表示、Windows・macOSでの起動、長時間利用時の一時保存の耐久性。ヘッドレス実行ではホスト全体のスクリーンショットにゲストの内容が合成されなかったため、描画の視覚確認にはゲストページのスクリーンショットを使用した。
