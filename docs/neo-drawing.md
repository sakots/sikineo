# neoの直接読み込みと描画

## 対象

Sikiの対象スレッドからneoを開き、描いた画像をSikiの投稿欄へ渡す。起動方法・添付契約は[画像引き渡しの仕様](image-attachment.md)を参照。レスの送信は利用者がSikiで行う。

## neoの読み込み

描画ページのscriptタグとlinkタグから、利用者指定の配布元を直接読み込む。

- JavaScript: https://oekakibbs.moe/apps/neo/neo.js
- CSS: https://oekakibbs.moe/apps/neo/neo.css

neo本体のダウンロード・ローカル配置・同梱は不要。プラグインのHTTPサーバーはneo本体を代理取得・配信しない。既存の`neo/`を読み込む互換経路や代替配布元へのフォールバックは作らない。

描画画面を開く際はインターネット接続が必要。配布URLの内容は更新されるため、固定バージョンの実行は保証しない。配布元のスクリプトは描画ページ上で実行され、描画内容や画像引き渡しのセッション情報にアクセスできる。指定配布元を信頼する前提で利用する。

CSPでは上記JavaScriptとCSSのURLだけを外部リソースとして許可する。画像引き渡しの通信は従来どおりローカルの同一オリジンに限定する。リソースを読み込めない場合は画面上に失敗を表示し、画像引き渡しを無効にする。接続を確認してからページを再読み込みする。

## 初期化

上流JavaScript、プラグインの初期化スクリプトの順に読み込む。`DOMContentLoaded`より前にSikiの対象サイズを`Neo.params.paintbbs`へ渡す。Electronを含むUser-Agentで上流の自動開始が抑止される場合は`Neo.start(false)`を呼ぶ。

## 描画と保存

- 5ch向けの描画サイズは500×250px。
- neo自身の投稿を隠し、`paintBBSCallback('check')`も`false`を返す。専用の画像引き渡しボタンでSikiへ渡し、自動送信は行わない。
- 表示レイヤーを白背景へ合成したPNGを使用し、自動リサイズや非可逆変換はしない。
- 引き渡しに失敗しても描画を残し、成功しても画面を勝手に閉じない。
- 一時保存・復元はneoの機能であり、確実な保存は保証しない。同じオリジンの描画画面は保存領域を共有するため、同時に開く画面は1つにする。
- 旧v0.2の300×300pxの保存領域は削除・移行しない。添付用画面のポート57831を維持し、旧ポート57830の一時保存を異なるサイズへ誤復元しない。

## 対応環境

Siki 0.43.12の内部描画保存処理を利用する。別バージョンの互換性は保証しない。直接読み込みの確認範囲は以下を参照。

## v0.4.0の検証結果

2026/11/05、公式Linux版Siki 0.43.12の隔離・ヘッドレス環境で確認。通常のデスクトップ表示、Windows・macOS、実スレッドへのレス送信は未検証。

- `pnpm test`: 3件成功。実装前にはローカルneoの有無より先に添付先を確認する回帰テストが503で失敗することを確認。
- neo本体を置かない配布物をSikiへ配置し、コマンドパレットから描画画面を起動。
- ブラウザのResource Timingとscript/linkのURLから、指定配布元のneo.js・neo.cssを直接読み込んでいることを確認。実行時のneoは1.8.15。
- 実マウス操作で500×250pxの描画画像にストロークを描き、Sikiの既存保存PNGとの一致と本文保持を確認。レスの送信操作は行っていない。
- 実ブラウザでJavaScript・CSSを個別に遮断し、それぞれのエラー表示、描画領域の非表示、引き渡しボタンの無効化を確認。
- CSSの遮断ではsheetが存在してもスタイルが適用されないケースを観測したため、リソースより先に登録したloadイベントで取得成功を確認する方式に変更。遮断解除後の再読み込みで描画と引き渡しが復旧することも確認。

v0.3.0以前のローカル配置型での添付先固定・入力欄保持などの確認結果は[画像引き渡しの仕様](image-attachment.md)を参照。
